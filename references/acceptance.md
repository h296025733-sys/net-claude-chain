# 实际验收

部署脚本成功后，由 Agent 用下面顺序实际打开和测试。用图形控制工具双击快捷方式，或从当前交互用户会话逐个运行对应的 .lnk。打开实际窗口并核对结果，再交付入口所在位置。在桌面找 `Claude 专用网络` 文件夹，Windows 使用 OneDrive 重定向桌面时也通过系统的桌面位置寻找。

1. 双击 **Claude 网页版**，确认专用 Chrome 或 Edge 的进程参数含自己的 profile 和环回 HTTP 代理，打开 Claude 官方网页并达到能交给用户登录的位置。Windows 有两种浏览器时可以再用 `claude-client.ps1 -Mode Check -Browser Edge` 等显式使用另一种验证。一般浏览器的登录状态与专用窗口分开。
2. 双击 **Claude 桌面端**，核对实际进程来自官方安装包并带环回代理参数。确认该进程或其子进程有环回代理连接，并核对没有该产品进程的外网直连。已有普通 Claude 窗口必须先退出。保存用户工作后测试专用进程退出会自动恢复。用户是否已经登录，单独记录。
3. 双击 **检测出口 IP**，检查 https://ip.net.coffee/ip/ 报告的 IP 与预期一致、地区为新加坡、类型为家庭住宅或 ISP。准确记录网站当时的风险和评分，网页检测结果只证明这个浏览器的出口。断开自己部署的代理，用同一专用浏览器验证公网请求失败，恢复后确认相同出口。实际有其他 VPN 在连时，再确认 VPS 使用物理路由、出口仍一致；明确记录具体测试的 VPN。
4. 检查代理的开机任务和桌面端的登录任务，检查运行状态和恢复。可用代理守护任务 `NetClaudeChain-Proxy`，复用时为 `NetClaudeChain-Route` 加已有的代理任务，桌面端为 `NetClaudeChain-Desktop`。整机重启、从未安装过的下载分支和两种浏览器都要按实测报告。
5. 交付入口的准确位置、当前测试结果与要由用户完成的登录。如截图会发给用户，裁掉或遮挡凭据、私人信息和完整订单标识。
